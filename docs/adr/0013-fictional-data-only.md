# 0013. Fictional data only in the repo

- **Status:** Accepted
- **Date:** 2026-09-13
- **Decided by:** Owner

## Context

Development uses the owner's real lab reports, and the repo is meant to be
published. The report files are sensitive personal data that must not be used
for training. Real data creeps into repos through test fixtures, sample files,
mockups, docs and commit messages.

## Decision

- Real reports and everything derived from them live only in gitignored folders:
  `1.reports/`, `2.images/`, `3.data/`, `.data/`.
- Everything committed uses fictional people and labs (Alex Tan, Sam Rivera,
  Northside Pathology, Harbour Medical Lab), generated by
  `scripts/generate-samples.ts` through the real pipeline.
- Mockups (Claude Design) and test fixtures use the same fictional data.
- When real scans are needed (e.g. comparing models), scripts print only counts
  and timings, and keep detailed output inside `.data/`.
- Before publishing, the repo and its full git history are searched for
  identifiers from the real reports.

## Consequences

- The repo can be published without scrubbing history.
- Fictional samples double as the browser development data and as import
  examples for anyone trying the app.
- Real-world accuracy can only be reported as totals.
